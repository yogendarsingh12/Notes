*Event Loop ->
 The JavaScript event loop is used to handle asynchronous tasks in JavaScript;
it continuously checks if the call stack is empty or not. If it is empty, then it picks tasks from the microtask queue until all tasks are not executed from the microtask queue; 
then it picks the macro task queue because the microtask has a higher priority. That's why it executes the microtask queue tasks first.
where micro tasks hold promises, and macro tasks hold events, timers, DOM manipulations, etc. 
What happens? Actually, first, synchronised or asynchronous tasks come in the call stack.
The synchronised task executes first and goes out from the call stack, and the asynchronous task is handled by the web API.
if The task is promised, and then it goes to the microtask queue; otherwise, it goes to the macro task queue. 
The event loop continuously checks call stack. 
If it is empty, then it first executes microtasks and then macros because microtasks have higher priority.

It has 2 phases: first, the memory creation phase, where all functions and variables get memory, 
and then the execution phase, where the task executes in a synchronous or asynchronous way.

[14]Event Delegations or Event Bubbleing or Capturing

->Event bubbling means when an event is triggered on a child element, it propagates upward through its parent elements.

->Event delegation is a technique where, instead of attaching multiple event listeners to individual child elements, we attach a single event listener to the parent element. It works mainly because of event bubbling.

->Event capturing is the opposite direction of bubbling. The event flows from the parent element toward the target child element. We can enable capturing by passing true as the third argument of addEventListener().
